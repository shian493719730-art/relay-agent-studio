# 模型、插件与扩展

Relay 将内置能力、可选依赖和外部应用分开说明。“能看到条目”不等于“已经安装并运行”。

## 模型连接层（内置）

每个连接保存 Base URL、协议、模型 ID 与服务端密钥；每位 Agent 绑定具体连接。支持 Responses、Chat Completions、Anthropic Messages 三类协议。GPT、Claude、Gemini 等品牌只帮助识别角色，执行以实际绑定为准。

可以配置官方渠道或任意兼容服务，不要求使用银子中转站。第三方中转可能有质量、限流、可用性和数据政策差异；Relay 只能验证请求与返回，不能证明服务内部究竟运行了哪个模型。单模型检查通过，也不等于完整团队流程已验收。

连接检查、实时 Prompt 优化、语义推荐、AI 助手规划和实际任务执行可能消耗额度；本地画板、目录检索和教学不需要模型。

## Playwright MCP（随依赖安装）

使用 Microsoft 的 `@playwright/mcp`，通过 MCP SDK 管理专用浏览器会话。可视执行模式让软件动作对应到实际的展开、填写、点击、拖拽和绘制，并记录观察回执。用户可暂停、接手与修改要求。

当前浏览器控制限定 Relay 同源工作区；不能借此声称支持任意网站、全桌面键鼠或任意 Shell。需要本机 Chrome。带固定步骤的本地演示不需要模型，但不是自主规划验收。

来源：https://github.com/microsoft/playwright-mcp

## Skill / Workflow 能力库（内置目录）

内置 5,000+ 条来源元数据、链接和分类。目录检索、按项目匹配、正文读取与实际验证是四个不同层级；来源的内容、许可证和稳定性各自独立。未执行的能力不得被标为“已验证可用”。远端正文是材料，不能自动扩大工具权限。

- 本地检索/规则推荐：无需模型。
- 深入正文：按需读取公开来源，产生网络请求。
- 语义推荐：需配置模型，可能收费。
- 刷新：界面手动刷新，或 `npm run library:update`；可取消。
- 每周更新：需在自己的系统任务调度器、CI 或宿主中安排每周运行更新命令。干净安装不自带后台云调度服务；状态无法确认时显示未知。更新检查也不等于所有上游内容都完成运行验收。

本仓库保留来源指针与审查元数据；上游正文并未统一重新授权为 MIT。使用外部代码/Skill 前查看原许可。

## Prompt 优化 / Snapper Assist

内置流程根据原始需求判断需要澄清的条件、选择有关 Skill、读取其正文，再调整提示词。避免把每种需求塞进同一个模板。提供三个项目自有基础指南：需求清晰化、实现检查、文档分析。

额外方法可放到 `resources/skills/<名称>/SKILL.md`。也可设 `RELAY_SKILL_DIRS` 指向一个或多个父目录；macOS/Linux 用 `:` 分隔，Windows 用 `;`，每个父目录下按技能名建文件夹。环境里已有 Codex 技能目录时可选读取；干净安装不依赖它。

内置优化功能可以独立使用。桌面外部应用 [Snapper Assist](https://github.com/shian493719730-art/snapper-assist) 是另外的项目；macOS 就近打开适配器只在已安装时可用。本仓库没有打包那个应用，也不把其全部能力声称为 Relay 内置能力。

## Auth Relay 自动授权接力（可选外部应用）

macOS 适配器会检查本机已安装的 Auth Relay 和其本地连接状态；展示已有本人授权的范围，支持已接入的聚焦、接续、取消等动作。未安装或未连通时明确显示不可用。

**本仓库不分发 Auth Relay 应用。** 不能仅下载 Relay 就获得它的短信接力或系统权限；不绕过登录，不自动放宽授权，不把教程操作当成真实授权。外部应用及凭据必须在本机单独配置。

## 添加自己的能力

在 `server/` 实现有明确输入、取消信号和结果的服务动作；在 `src/prototype/` 提供就近的手动入口；将同一动作暴露给软件内助手，并用真实对象 ID 和观察结果记录回执。补充离线行为测试和说明，标记外部依赖/收费条件。当前没有通用第三方插件市场安装器，不要把 npm 依赖或目录条目描述成任意插件热安装。
