# Relay：面向 vibe coder 的可视化办公软件

## 为谁解决什么问题

面向通过自然语言与 AI 一起完成任务、也希望亲手调整工作环境的人。工作可能涉及代码，也可能是文件整理、内容运营、研究、材料分析、审阅和跨项目交接。Relay 把这些任务放进可操作的画板，让人看到谁在做、材料来自哪里、结果交给谁，以及哪里需要接手。

## 四个相互配合的部分

| 部分 | 使用者得到什么 | 当前入口与边界 |
| --- | --- | --- |
| 可视化办公空间 | 亲手画项目、放文件、写笔记、组团队、调布局；执行可暂停，编辑可撤销。 | 画板与项目对话；保留手绘轮廓、品牌身份色和按需呼出的面板。 |
| 多模型协作与软件助手 | 根据目标分工、读取材料、调用软件动作、汇总，并交给下游项目。 | 每位成员独立连接；真实推理需要自己的 API。未接入的外部动作明确报缺失。 |
| GitHub 开源资源持续供给 | 按项目寻找适用的 Skill、Workflow 与工具，查看正文、来源和许可，跟进上游变化。 | 能力库、项目推荐、Prompt 优化；收录/读取/运行分别标记，每周任务需要宿主或自配调度。 |
| Auth Relay 授权接力 | 把需要本人处理的验证步骤留在流程中，查看范围、接手、接续和取消。 | 软件已内置 UI 与任务桥；需要另装 macOS Auth Relay，沿用已有授权。 |

## 一次办公任务如何经过这些能力

将需求文档拖入项目，先检查读到的正文；在能力库按目标寻找合适方法，用相关 Skill 推敲任务表达；让统筹与各自绑定模型的成员完成分工，用户随时改要求或停止。成果送到审核项目后，再通过明确的共享规则交给复盘或其他下游项目。若已接入的外部任务遇到本人验证，使用授权接力入口处理，并核对原任务状态再继续。

例如内容运营可以拆成选题、待审稿、人工审核和复盘。真实平台发布、平台数据采集或其他业务服务仍需单独集成；本地教学中的模拟发布和样例指标不代表这些服务已经接通。

## 交付与可操控性

现阶段为本地单用户 Web Alpha。主画板不常驻额外后台侧栏；文件、模型、工具、权限都在需要时呼出。保留布局、组件、样式的手动编辑，助手通过可观察软件动作执行，不自动覆盖用户的工作空间。恢复对象不会自动恢复收费调用。

公开介绍中的“持续更新”是维护来源的定期检查与手动刷新，不是实时全网抓取；“自动授权”是已有本人授权下的任务接力，不是替用户无限授权；“资源供给”不代表任何上游代码都已经自动安装和验证。
