# 在 Relay 中开发 Relay

源码工作区把真实 Git 仓库接进项目画板。内置助手可以读取文件、根据实际版本写入或替换片段、查看差异、运行已允许的检查，以及回滚具体修改。手动编辑与助手使用同一套本机能力；代码建议、画板笔记和真正落盘有明确区别。

## 人人都能走完的源码课程

在「新手教程」中选择 **人人都能自开发 → 开始源码自开发课程**；源码面板也有同名入口。8步用带编号的箭头指向实际鼠标控件，不要求记快捷键：

1. 新建独立的本地源码练习工程。
2. 阅读真实 README，了解需求和测试。
3. 打开 `src/welcome.mjs`，读取实际源码。
4. 把欢迎语改为「我的 Relay 工作台」，亲手保存到磁盘。
5. 在「检查与日志」运行真实测试，等待退出码0。
6. 打开本轮差异，核对修改前后。
7. 回滚本轮修改，重新读取并确认原始欢迎语。
8. 再测：原始欢迎语不符合新需求，应再次出现该断言失败。这是回滚验证，课程不会把它显示成测试通过。

桌面包使用内置 Node；源码服务使用自身正在运行的 Node。练习**不需要 Git、npm、API 密钥、模型额度或下载依赖**。本机生成4个普通文件，只在该练习工程内读写。测试、日志、版本冲突保护和回滚使用正式源码桥，不是预设成功动画。语法检查仅核对 JavaScript 语法，不冒充 TypeScript 类型检查；练习的1个测试也不等同于 Relay 全部测试。

课程可以暂停、收拢和继续；暂停会停止本轮未结束的检查，回到原画板并保留文件、草稿、日志和课程断点，恢复不自动重跑。练习板关闭了模型入口，不会因教程自动开启收费执行。检查仍按本机账号执行，不是 OS 安全沙箱。

完成后可点击「连接自己的源码」，把同一套读写、测试和回滚能力用于自己的项目；人人得到相同入口，不依赖维护者的电脑路径、账号或中转站。自己的仓库仍需要 Git 和对应开发环境，真实 AI 协作另需自行配置模型。当前练习不修改 Relay 安装文件；要开发 Relay 自己，请连接其源码仓库。

## 从现有项目进入

1. 打开左上「画板」菜单 →「源码开发」，或在项目详情/聊天顶部打开「源码」。
2. 填写本机 Git 仓库的绝对路径，点击「检查目录与脚本」。普通画板无需开发环境；源码开发需要本机 Git、Node.js/npm，Relay 构建还需要 Python 3。此功能不会替你安装依赖。
3. 选择现有项目，或新建开发项目。新项目带统筹、代码实现、复核验证三个角色；尚未绑定实际模型时不会推理。
4. 根据需要开启源码写入和列出的检查脚本，再连接。连接目录是手动操作，助手不能自行增加一个目录或扩大其权限。
5. 在文件页读取、编辑与保存；在「差异与回滚」核对前后内容，在「检查与日志」运行类型检查、测试或构建。

把 Relay 自己作为开发对象时，选择你克隆的 `relay-agent-studio` 仓库。macOS 建议放在 `~/Developer/relay-agent-studio`；本机验收中，桌面目录的 Git 子进程曾超时，独立 Developer 目录成功。遇到 `spawnSync git ETIMEDOUT` 时先确认 Git 可用并换到正常可访问的开发目录，不要自动扩大系统目录权限。不要选择含私人业务、密钥和运行数据的上层目录；桌面应用的安装文件也不是可编辑源码仓库。当前应用不会自动热替换自己的安装包，源码改好后需要构建并安装新版本，或在独立开发服务中预览。

## 内置 Agent 如何使用

在「AI 助手」描述具体改动与验收条件。例如：“先读文件，修复这个问题，保存最小修改，查看 Git diff，运行类型检查和测试；遇到冲突先保留，不覆盖我的手动修改。”

| 软件动作 | 真实结果 |
| --- | --- |
| `dev.status` / `dev.files` | 当前画板已连接仓库、项目权限和可见文件；没有连接则要求用户先连接 |
| `dev.read` | 实际磁盘正文、版本 hash 和分页位置 |
| `dev.write` / `dev.replace` / `dev.delete` | 实际源码修改，返回独立 changeId 和前后版本；旧 hash 会被拒绝 |
| `dev.diff` / `dev.gitDiff` | 本机修改记录、前后正文，或选定文件真实 Git diff；长输出注明分页/截取 |
| `dev.check` / `dev.checkStatus` / `dev.stop` | 真实本机进程、日志、退出码与停止状态；只有 passed 才表示检查通过 |
| `dev.revert` / `dev.reapply` | 回滚/重做具体一次修改，不重置整个仓库，不覆盖后续人工编辑 |

这些动作会打开对应面板，保留步骤与回执。未保存的手动草稿不会被 Agent 覆盖；发生版本冲突时要先重新读取或处理草稿。助手暂停会停止它正在等待的检查，保留完成步骤和日志。停止的编译/测试进程不能从内部断点续跑，需要明确重新运行；不能把停止称为通过。

这一版 dev.* 接给内置软件操作助手。协作成员仍通过各自绑定模型产出内容；操作助手可以先读取所选源码、存为项目材料，再组织团队分析并应用实际产出。源码落盘、检查和回滚由操作助手或用户调用本机桥完成，未给每个成员独立文件系统或 Shell 权限。

## 键鼠与源码桥接的分工

Playwright MCP 继续负责 Relay 浏览器中的真实点击、填写、拖拽和可视接手。源码通过本机文件桥落盘，检查通过明确列出的本机任务运行；不会假装是用键盘“打字”改了文件。可视模式对这类操作使用对应动作卡并等待真实回执。目前没有任意桌面应用或无限制 Shell 控制。

## 数据、权限与恢复

- 访问限定所连接的 Git 仓库，或应用生成的独立练习工程。符号链接、目录穿越、Git 忽略文件、密钥文件、依赖、构建和运行目录不开放给源码动作。读取支持普通 UTF-8 文本，单文件上限1MB；大文件可分页读取、精确替换。
- 检查只开放项目已存在的 `typecheck`、`test`、`build` 脚本。连接时展示其正文；package.json 改变后需重新核对和允许。不会执行传入的任意命令，也不会自动安装或发布。
- **本机检查会运行仓库代码，使用你的账号权限，并非操作系统沙箱。** 只连接你信任的项目；任意第三方项目的脚本可能有网络和文件副作用。Relay 自身的离线测试使用模拟模型，本轮验收不调用收费模型。
- 修改备份、工作区连接和检查记录保存在本机服务数据目录的 `development/` 中，不发布到 GitHub。源码草稿存在该工作区的浏览器存储中。不要公开分享运行数据或完整备份。
- 源码回滚与画板撤销分开；删除开发项目会停止对应检查，恢复项目不会自动重启检查。断开源码连接保留文件与记录。关闭面板不停止检查；退出桌面应用会停止其检查进程。
- 用户配置的模型会收到选定源码和检查回执，真实推理仍需有效连接和额度。当前没有自动 Git 提交、推送、部署或任意软件控制；这些不能从“源码检查通过”推断为已完成。

维护平台为 macOS、Linux；Windows 不作为本功能验收条件，见[平台范围](PLATFORMS.md)。
