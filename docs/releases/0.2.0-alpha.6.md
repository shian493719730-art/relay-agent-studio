# Relay 0.2.0-alpha.6

Relay's built-in operator can now use a general Git/npm development toolchain, beyond the fixed welcome-copy lesson. Describe a concrete change after connecting and reviewing a project: the operator can install dependencies, read and edit actual source, run allowed tests/builds, start the application, inspect its actual page and package outputs.

- **Independent development environments:** npm install/ci runs in a source copy; original node_modules stays intact. A generated lockfile is written back with version checks and a visible source change receipt. Dependency changes do not authorize new script bodies.
- **Visible execution:** source panel → Development & preview shows real logs, exit codes, attempts and artifacts. Stop/pause terminates descendants; explicit continuation restarts that command and preserves completed edits. Opening the assistant or project setup does not execute commands or models.
- **Actual application preview:** a running local HTTP process is embedded in the workspace. A separate Playwright MCP browser can read the page and return a screenshot/DOM observation. Chrome is needed for browser inspection; HTTP readiness alone is not a functional test. The desktop preview uses a separate origin and does not pass the main app's credentials.
- **Real packages:** newly generated ZIP/TGZ/DMG and similar artifacts have checksums and download/export controls. Web builds can be streamed into a ZIP. Stale files cannot turn a no-output command into a successful package. Historical copies remain available after rollback.
- **Development checkpoints:** restore the actual source changes, lockfile and previous dependency environment together. Later manual edits cause a conflict instead of being overwritten. Restoration does not restart previews or models.
- **Bundled Node/npm:** supported desktop packages include standalone development tools and their license notices. Git remains required for connected repositories; building Relay also needs Python. Source deployments use their installed tools.

The editable canvas, palette, positions, drafts and floating-panel approach remain. The old free lessons are available separately. Normal development has manual controls and operator actions; it is not a predetermined lesson.

Validation uses real files, npm commands, HTTP servers, process termination, ZIP outputs, desktop isolation and a simulated planner; **no paid provider calls were made**. Real model end-to-end acceptance remains pending. Maintained packaging targets are macOS arm64 and Linux x64; Windows remains experimental and is not a release requirement.

Current formal package manager support is npm, using the public npm registry without reusing private registry credentials. Install hooks and implicit pre/post hooks are disabled; explicitly reviewed project scripts can perform needed initialization. Commands run as the local user, not in an OS sandbox, and cannot undo arbitrary external effects initiated by project code. There is no automatic Git push, deployment, model quota purchase or replacement of the running installation. AGPL-3.0-only and separate brand rules continue; historical MIT grants remain unchanged.

Community macOS packages are ad-hoc signed, without Developer ID notarization. No system protection bypass is part of this release.
