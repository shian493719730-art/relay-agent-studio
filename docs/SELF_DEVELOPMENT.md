# 在 Relay 中开发 Relay

源码工作区把真实 Git 仓库接进项目画板。内置助手可以读取文件、根据实际版本写入或替换片段、查看差异、运行已允许的检查，以及回滚具体修改。手动编辑与助手使用同一套本机能力；代码建议、画板笔记和真正落盘有明确区别。

## 人人都能走完的源码课程

在「新手教程」中选择 **人人都能自开发 → 开始源码自开发课程**；源码面板也有同名入口。8步用带编号的箭头指向实际鼠标控件，不要求记快捷键：

1. 新建独立的本地源码练习工程。
2. 阅读真实 README，了解需求和测试。
3. 打开 `src/welcome.mjs`，读取实际源码。
4. 把欢迎语改为「我的 Relay 工作台」，亲手保存到磁盘。
5. 在「检查与日志」运行真实测试，等待退出码0。
6. 打开本轮差异，核对修改前后。
7. 回滚本轮修改，重新读取并确认原始欢迎语。
8. 再测：原始欢迎语不符合新需求，应再次出现该断言失败。这是回滚验证，课程不会把它显示成测试通过。

桌面包使用内置 Node；源码服务使用自身正在运行的 Node。练习**不需要 Git、npm、API 密钥、模型额度或下载依赖**。本机生成4个普通文件，只在该练习工程内读写。测试、日志、版本冲突保护和回滚使用正式源码桥，不是预设成功动画。语法检查仅核对 JavaScript 语法，不冒充 TypeScript 类型检查；练习的1个测试也不等同于 Relay 全部测试。

课程可以暂停、收拢和继续；暂停会停止本轮未结束的检查，回到原画板并保留文件、草稿、日志和课程断点，恢复不自动重跑。练习板关闭了模型入口，不会因教程自动开启收费执行。检查仍按本机账号执行，不是 OS 安全沙箱。

完成后可点击「连接自己的源码」，把同一套读写、测试和回滚能力用于自己的项目；人人得到相同入口，不依赖维护者的电脑路径、账号或中转站。自己的仓库仍需要 Git 和对应开发环境，真实 AI 协作另需自行配置模型。当前练习不修改 Relay 安装文件；要开发 Relay 自己，请连接其源码仓库。

## 正式开发：按具体需求工作

「新手教程 → 真实项目开发 → 连接真实项目」或源码面板的 **开发与预览** 打开正式工具。此入口使用你自己的 Git/npm 工程，支持任意已授权源码文件，独立于预设的文案课程。

首次检查目录时，在「项目开发：安装依赖、预览与打包」允许安装依赖，并逐条核对要执行的实际脚本。依赖声明变化不会自行增加脚本权限；脚本原文变化后需要重新核对。然后点击 **让AI开发这个项目**，写清要增加或修复的功能。按钮只打开需求输入，不启动模型；明确执行后才由已配置模型分析、调用工具、读取真实结果和继续修正。

正式工具链包含：

- 建立本轮回滚点，读取实际源码与 hash，按版本修改文件。手动编辑和 AI 编辑使用同一差异记录。
- 在独立的开发副本中执行 npm install/ci，安装 package.json 声明的依赖，保留原仓库的 node_modules。新锁文件按原版本核对后回写，冲突时保留人工修改。
- 执行已允许的测试、构建等项目脚本。日志实时显示，退出码与失败信息来自实际进程。默认禁用 npm 自动安装钩子和隐式 pre/post 脚本；需要的初始化应配置成明确可核对的项目脚本。[npm 的脚本行为](https://docs.npmjs.com/cli/npm-ci/)。
- 启动应用预览，等待本机 HTTP 服务就绪；在面板直接浏览应用。Vite/Next 使用分配的回环端口，其他项目脚本需接受 PORT 环境变量。可在「预览设置」填写入口路径。Relay 先运行 build 生成画板：使用 dev 预览时填写 /design-v2/index.html；使用构建后的 start 服务时填写 /design-v2/。Vite 对目录请求可能返回 SPA 首页，必须核对实际页面而不能只看 HTTP 200。预览显示启动时源码，修改后重启预览。预览运行时占用该项目环境，继续测试或打包前先暂停预览。
- **检查实际页面** 通过隔离的 Playwright MCP 浏览器读取实际 DOM 并截图，结果回到原面板和助手。此检查需要 Chrome；仅 HTTP 可用不等于功能通过。桌面预览使用独立来源，只代理本服务当前启动的任务，不传递主 App 的凭据。当前不代理 HMR WebSocket，使用重启预览查看新版本。
- 执行已允许的打包脚本，保存本次实际生成的 ZIP、TGZ、DMG 等文件及 SHA-256；普通 Web 构建可归档为 project-build.zip。旧输出不能冒充本次成功产物。归档使用流式 ZIP，等待写入完成再提供下载。[Archiver 的完成与错误处理](https://www.archiverjs.com/docs/quickstart/)。

每一步可暂停，进程及子进程会停止；**继续本步** 创建新的尝试，重启本步命令，已完成的源码编辑不重复。关闭面板保留执行和记录；暂停助手、项目全部停止或删除项目会停止相关开发步骤。服务重启不会自动恢复命令或模型调用。

**恢复本轮源码与环境** 会停止相关执行，逆序恢复该回滚点下的源码差异和锁文件，切回先前依赖环境。若文件有后续人工修改则拒绝覆盖，先处理冲突。恢复不会启动预览或收费调用。独立开发副本、日志与产物历史保留；历史包不表示当前源码已重新通过验证。脚本在开发副本生成的其他源文件不会悄悄覆盖原仓库，需要读取结果后明确写入。

这一版正式环境维护 Git/npm 工程；桌面正式开发自带 Node/npm，自己的工程仍需 Git；源码服务使用本机 Node/npm，Relay 构建还需 Python。依赖安装默认使用 npm 官方公共 registry，不复用私人 npm 凭据；其他包管理器与私有 registry 认证尚未接入。项目脚本按本机账号执行，独立副本不是 OS 安全沙箱，无法回滚第三方脚本主动写到工程外的系统或远端服务。工具没有自动 Git 推送、部署、发布或替换当前安装包能力。

收费模型仍需用户自行配置和明确执行。本次验证采用实际项目、真实 npm/浏览器/文件/产物和模拟规划器，未调用收费模型，不能把模拟规划器验收称作模型自主开发验收。

## 连接与权限

1. 打开左上「画板」菜单 →「源码开发」，或在项目详情/聊天顶部打开「源码」。
2. 填写本机 Git 仓库的绝对路径，点击「检查目录与脚本」。普通画板无需开发环境；连接源码需本机 Git。桌面正式开发自带 Node/npm，源码服务需本机 Node/npm，Relay 构建另需 Python 3。在下方明确允许依赖安装后，才可以在独立副本安装项目依赖。
3. 选择现有项目，或新建开发项目。新项目带统筹、代码实现、复核验证三个角色；尚未绑定实际模型时不会推理。
4. 根据需要开启源码写入和列出的检查脚本，再连接。连接目录是手动操作，助手不能自行增加一个目录或扩大其权限。
5. 在文件页读取、编辑与保存；在「差异与回滚」核对前后内容，在「检查与日志」运行类型检查、测试或构建。

把 Relay 自己作为开发对象时，选择你克隆的 `relay-agent-studio` 仓库。macOS 建议放在 `~/Developer/relay-agent-studio`；本机验收中，桌面目录的 Git 子进程曾超时，独立 Developer 目录成功。遇到 `spawnSync git ETIMEDOUT` 时先确认 Git 可用并换到正常可访问的开发目录，不要自动扩大系统目录权限。不要选择含私人业务、密钥和运行数据的上层目录；桌面应用的安装文件也不是可编辑源码仓库。当前应用不会自动热替换自己的安装包，源码改好后需要构建并安装新版本，或在独立开发服务中预览。

## 用自然语言让内置助手开发 Relay

「新手教程 → 用自然语言修改 Relay」补上助手代操作的完整流程，不需要你手写代码。

### 先走本地课程（不运行模型）

在正常的助手需求输入框写：**把 Relay 内置助手的开场说明改成「先说目标，我们一起完成。」；保留其他功能，运行测试并展示结果。** 可以换成你想要的短文案。点击「执行本地自开发演练」。

本地课程仅提取引号中的开场文案字段，按明确的预设工具流程执行，不进行开放式模型理解。软件操作助手会建立独立源码副本，读取正式使用的 `resources/ui/assistant-copy.json` 和验收代码，基于实际 hash 精确修改，再运行真实 Node 测试、查看差异，并用真实助手相同的组件显示源码结果。需求与测试文件在本课为只读，不能靠改验收标准冒充通过。

默认「逐步执行」在每步完成后暂停，点击「继续下一步」接续；取消勾选可自动完成后续本地步骤。每步有真实回执和进度，支持中途暂停。被停止的检查要在你明确继续后重跑，已完成的读取和修改不会重复。窄窗口在助手中展示实际回执，点击「查看源码 / 预览」切换到文件面板，再返回进度。

完成后点击「回滚本轮修改」，助手使用本轮 changeId 回滚、重读磁盘并核对原始版本，展示恢复后的组件。后续人工更改会触发冲突，不会被回滚覆盖。结果记录保存在练习项目；原仓库和安装包保留，源码预览不等于安装包已热更新。

### 再准备真实 AI（本轮不自动执行）

点击「准备真实AI开发（不执行）」返回自己的工作区，得到自然语言开发草稿和准备清单：

1. 连接自己克隆的 Relay Git 仓库，核对读写及检查脚本权限。
2. 在助手「执行设置与可用能力」选择你配置的实际模型；可以用官方接口、自定义中转或兼容的本地服务。
3. 核对需求与验收条件。真实助手会读取源码、分析、调用 dev.*、观察实际测试和预览结果再继续；使用同样的可见回执、暂停和逐次回滚工具。
4. 准备不会调用模型。只有你明确点击执行才进入模型推理，可能产生供应商费用；无有效仓库/权限时先停止，不发送模型请求。

当前收费模型验收仍暂停。对真正源码的修改需要构建/安装或独立预览才能改变应用；本功能不会自动推送、部署或替换安装包。真实模型端到端效果不能从本地预设课程或模拟规划器推断。

## 内置 Agent 如何使用

在「AI 助手」描述具体改动与验收条件。例如：“先读文件，修复这个问题，保存最小修改，查看 Git diff，运行类型检查和测试；遇到冲突先保留，不覆盖我的手动修改。”

| 软件动作 | 真实结果 |
| --- | --- |
| `dev.status` / `dev.files` | 当前画板已连接仓库、项目权限和可见文件；没有连接则要求用户先连接 |
| `dev.read` | 实际磁盘正文、版本 hash 和分页位置 |
| `dev.write` / `dev.replace` / `dev.delete` | 实际源码修改，返回独立 changeId 和前后版本；旧 hash 会被拒绝 |
| `dev.preview` | 读取实际助手文案源码，以同一个组件展示结果及对应测试版本；未热替换安装包 |
| `dev.diff` / `dev.gitDiff` | 本机修改记录、前后正文，或选定文件真实 Git diff；长输出注明分页/截取 |
| `dev.check` / `dev.checkStatus` / `dev.stop` | 真实本机进程、日志、退出码与停止状态；只有 passed 才表示检查通过 |
| `dev.revert` / `dev.reapply` | 回滚/重做具体一次修改，不重置整个仓库，不覆盖后续人工编辑 |
| `dev.install` / `dev.run` / `dev.serve` / `dev.package` | 在独立开发副本安装声明的依赖、运行已核对的脚本、预览和保存本次产物 |
| `dev.inspectPreview` / `dev.taskStatus` | 读取实际应用页面与截图、查看进程日志和实际退出状态 |
| `dev.pauseTask` / `dev.resumeTask` / `dev.rollbackTask` | 停止进程、明确重试本步或恢复本步环境；保留真实记录 |
| `dev.checkpoint` / `dev.restoreCheckpoint` | 建立本轮回滚点，按版本恢复源码差异、锁文件及依赖环境 |

这些动作会打开对应面板，保留步骤与回执。未保存的手动草稿不会被 Agent 覆盖；发生版本冲突时要先重新读取或处理草稿。助手暂停会停止它正在等待的检查，保留完成步骤和日志。停止的编译/测试进程不能从内部断点续跑，需要明确重新运行；不能把停止称为通过。

这一版 dev.* 接给内置软件操作助手。协作成员仍通过各自绑定模型产出内容；操作助手可以先读取所选源码、存为项目材料，再组织团队分析并应用实际产出。源码落盘、检查和回滚由操作助手或用户调用本机桥完成，未给每个成员独立文件系统或 Shell 权限。

## 键鼠与源码桥接的分工

Playwright MCP 继续负责 Relay 浏览器中的真实点击、填写、拖拽和可视接手。源码通过本机文件桥落盘，检查通过明确列出的本机任务运行；不会假装是用键盘“打字”改了文件。可视模式对这类操作使用对应动作卡并等待真实回执。目前没有任意桌面应用或无限制 Shell 控制。

## 数据、权限与恢复

- 访问限定所连接的 Git 仓库，或应用生成的独立练习工程。符号链接、目录穿越、Git 忽略文件、密钥文件、依赖、构建和运行目录不开放给源码动作。读取支持普通 UTF-8 文本，单文件上限1MB；大文件可分页读取、精确替换。
- 旧源码检查保留 `typecheck`、`test`、`build` 入口；正式开发环境可执行用户逐条核对的项目现有脚本。脚本原文改变后需重新核对，依赖变更不会扩大脚本权限。安装依赖需单独允许，不接受助手传入的任意 Shell 命令，也不自动发布。
- **本机检查会运行仓库代码，使用你的账号权限，并非操作系统沙箱。** 只连接你信任的项目；任意第三方项目的脚本可能有网络和文件副作用。Relay 自身的离线测试使用模拟模型，本轮验收不调用收费模型。
- 修改备份、工作区连接和检查记录保存在本机服务数据目录的 `development/` 中，不发布到 GitHub。源码草稿存在该工作区的浏览器存储中。不要公开分享运行数据或完整备份。
- 源码回滚与画板撤销分开；删除开发项目会停止对应检查，恢复项目不会自动重启检查。断开源码连接保留文件与记录。关闭面板不停止检查；退出桌面应用会停止其检查进程。
- 用户配置的模型会收到选定源码和检查回执，真实推理仍需有效连接和额度。当前没有自动 Git 提交、推送、部署或任意软件控制；这些不能从“源码检查通过”推断为已完成。

维护平台为 macOS、Linux；Windows 不作为本功能验收条件，见[平台范围](PLATFORMS.md)。
